- **E5 — production compose** — `deploy/docker-compose.yml` does not exist yet (only `docker-compose.dev.yml`). Its Redis must get a named volume and an explicit persistence choice (AOF `appendonly yes` or RDB `save`). Without persistence a restart loses: admin sessions (users sign in again), preview tokens, rate-limit counters, "Verifică instalarea" timestamps and the recently cited documents (E4b.1 UX 13). All of that is acceptable to lose (the cited documents are only suggestions; installations are seen again at the next page view), but it should be a decision, not an accident. In the dev compose Redis has no named volume: the image's default RDB snapshots live in an anonymous volume, kept across restarts of the same container but lost on `down`.
